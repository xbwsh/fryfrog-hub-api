# 重构计划：NFO + 轻量存储 混合架构

## 已确认的设计决策

1. **音乐元数据**：音频内嵌标签为主，NFO 仅补充扩展信息（如 artistBio）
2. **API ID 策略**：文件路径（String）作为唯一标识，替代数据库自增 ID
3. **数据迁移**：启动时自动检测旧表并迁移，完成后标记跳过

## 目标

将媒体元数据从 SQLite 数据库迁移到 NFO 文件，SQLite 仅保留用户状态和系统配置。去掉 JPA/Hibernate，用 JdbcTemplate 直连。

## 当前状态 → 目标状态

| 类别 | 当前 | 目标 |
|------|------|------|
| 媒体元数据 | SQLite (JPA Entity) | NFO 文件 (XML) |
| 播放/阅读进度 | SQLite (JPA Entity) | SQLite (JdbcTemplate) |
| 收藏/播放统计 | Entity 字段 (favorite, playCount) | SQLite 新表 (JdbcTemplate) |
| 播放列表 | SQLite (JPA Entity) | SQLite (JdbcTemplate) |
| 系统设置 | SQLite (JPA Entity) | SQLite (JdbcTemplate) |
| 媒体库配置 | SQLite (JPA Entity) | SQLite (JdbcTemplate) |
| 系列信息 | SQLite (JPA Entity) | NFO 文件 |
| 角色/演员信息 | SQLite (JPA Entity) | NFO 文件 |

### 3. SQLite 保留的表（用户状态 + 配置）

```sql
-- 系统配置（保持不变）
CREATE TABLE system_setting (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    key TEXT NOT NULL UNIQUE,
    value TEXT,
    description TEXT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- 媒体库配置（保持不变）
CREATE TABLE media_libraries (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    path TEXT NOT NULL,
    type TEXT NOT NULL,        -- MUSIC/COMIC/VIDEO/EBOOK
    sub_type TEXT,             -- MOVIE/TV/MIXED
    enabled BOOLEAN DEFAULT 1,
    sort_order INTEGER,
    description TEXT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- 视频观看进度（保持不变）
CREATE TABLE watch_progress (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    video_id INTEGER NOT NULL UNIQUE,  -- 存文件路径的 hash 或 NFO key
    position_seconds REAL,
    duration_seconds REAL,
    completed BOOLEAN DEFAULT 0,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- 漫画阅读进度（保持不变）
CREATE TABLE comic_reading_progress (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    comic_id INTEGER NOT NULL UNIQUE,  -- 存文件路径的 hash 或 NFO key
    current_page INTEGER,
    total_pages INTEGER,
    completed BOOLEAN DEFAULT 0,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- 电子书阅读进度（保持不变）
CREATE TABLE ebook_reading_progress (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ebook_id INTEGER NOT NULL UNIQUE,  -- 存文件路径的 hash 或 NFO key
    current_page INTEGER,
    total_pages INTEGER,
    completed BOOLEAN DEFAULT 0,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- 新增：用户状态表（合并 favorite + playCount + lastPlayedAt）
CREATE TABLE user_media_state (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    media_key TEXT NOT NULL UNIQUE,     -- 文件路径或唯一标识
    media_type TEXT NOT NULL,           -- MUSIC/COMIC/EBOOK/VIDEO
    favorite BOOLEAN DEFAULT 0,
    play_count INTEGER DEFAULT 0,
    last_played_at TIMESTAMP,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- 播放列表（保持不变）
CREATE TABLE playlists (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    description TEXT,
    cover_url TEXT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- 播放列表曲目（保持不变）
CREATE TABLE playlist_tracks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    playlist_id INTEGER NOT NULL,
    track_key TEXT NOT NULL,            -- 音乐文件路径
    added_at TIMESTAMP,
    position INTEGER,
    FOREIGN KEY (playlist_id) REFERENCES playlists(id)
);
```

**关键设计决策**：进度和用户状态表使用 `media_key`（文件路径）作为关联标识，而非数据库自增 ID。这样 NFO 文件和数据库之间通过文件路径关联。

### 4. API ID 策略（已确认：文件路径作为 ID）

**变更点**：当前所有 API 返回的 `id` 字段是 Long 类型自增 ID。重构后改为 String 类型的文件路径。

影响范围：
- `VideoController`：`/{id}` → id 从 Long 变为 String（文件路径）
- `MusicController`：`/{id}` → 同上
- `ComicController`：`/{id}` → 同上
- `EbookController`：`/{id}` → 同上
- 所有进度/收藏 API 的路径参数

**兼容性考虑**：
- URL 中的路径需要 URL 编码（`/` → `%2F`）
- 前端需要适配新的 ID 格式
- 如果前端改动量太大，备选方案：用 `hashCode()` 生成 int 作为 ID（保持 Long 类型），但不可读

**推荐**：直接用文件路径，URL 编码处理。API 响应中同时返回 `id`（路径）和 `fileName`（显示用）。

### 6. 数据迁移策略

启动时自动迁移（`ApplicationRunner`）：
1. 检测旧表是否存在（`videos`/`music_tracks`/`comics`/`ebooks`）
2. 如果存在，读取所有旧表数据
3. 为每个实体生成对应的 NFO 文件
4. 迁移 favorite/playCount/lastPlayedAt → `user_media_state` 表
5. 迁移进度表的 ID 关联 → media_key（文件路径）
6. 迁移完成后重命名旧表（`_backup` 后缀），不直接删除
7. 设置 `migration.completed=true` 标记到 `system_setting`，下次启动跳过

## 验证方案

1. **构建验证**：`mvn clean compile` — 确保无编译错误
2. **单元测试**：`mvn test` — 确保现有测试通过（需适配）
3. **迁移验证**：
   - 启动应用，执行数据迁移
   - 检查生成的 NFO 文件内容正确性
   - 检查 `user_media_state` 表数据正确性
4. **功能验证**：
   - 启动应用，扫描媒体库
   - 调用所有列表/搜索 API，确认返回数据正确
   - 调用进度保存/读取 API
   - 调用收藏切换 API
   - 调用播放列表 CRUD API
   - 调用视频/音频流播放 API
   - 调用 TMDB/Bangumi 刮削 API，确认 NFO 生成正确
5. **删除数据库验证**：删除 fryfrog.db，重启应用，重新扫描，确认可以从 NFO 重建所有元数据

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| NFO 文件被意外删除 | 扫描时发现缺失可从备份表重建；日志告警 |
| 大量文件扫描慢 | 按库增量扫描，仅扫描变化的文件；后台异步 |
| SQLite 并发写锁 | 保持现有 busy_timeout 配置，JdbcTemplate 事务管理 |
| 音乐 NFO 与音频标签不一致 | 以音频标签为主，NFO 仅补充；冲突时以音频标签为准 |
| API id 类型从 Long 变 String | 前端需适配；URL 中路径需编码 |
| 迁移过程出错 | 旧表重命名而非删除，可回滚 |

## 注意事项

- `MediaSeries` 和 `MediaSeriesCharacter` 目前在 common 模块，被 comic 和 ebook 共享。重构后它们由各自的 NFO 驱动，但仍需保留 DAO 用于系列分组查询
- 测试目前只有 music 模块有 1 个测试类，需要在重构后补充关键路径测试
- `@Retryable`（comic 模块）在去掉 JPA 后可能不再需要，但 SQLite 并发写锁仍需注意
