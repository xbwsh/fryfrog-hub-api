# Plan: Remove FFmpeg and Media Info Fields

## Goal
Remove all FFmpeg/ffprobe dependencies and media info fields (codec, resolution, framerate, etc.) from the database, since the frontend MPV player now handles these natively.

## Fields to REMOVE from Video entity
`videoCodec`, `videoProfile`, `pixFmt`, `displayAspectRatio`, `audioCodec`, `audioChannelLayout`, `resolution`, `frameRate`, `bitrateKbps`

## Fields to KEEP (not ffprobe-dependent)
- `durationMinutes` — set by TMDB scraping and NFO parsing
- `durationSeconds` — used by WatchProgressService for playback progress
- `format` — set from file extension in VideoScanService

## Changes

### 1. Delete files
- `video/src/main/java/.../service/MediaInfoService.java` — entire file (ffprobe wrapper)
- `video/src/main/java/.../util/FFmpegBinaryExtractor.java` — entire file (FFmpeg binary extraction)

### 2. Video.java (entity)
Remove 9 fields: `videoCodec`, `videoProfile`, `pixFmt`, `displayAspectRatio`, `audioCodec`, `audioChannelLayout`, `resolution`, `frameRate`, `bitrateKbps`

### 3. VideoDTO.java
- Remove same 9 fields + their setter calls in `fromEntity()`
- Remove `INCOMPATIBLE_AUDIO` set, `audioIncompatible` field, and its setter logic

### 4. VideoController.java
- Remove `MediaInfoService` import and field
- Remove 3 endpoints: `getMediaInfo()` (`/media-info`), `getSubtitles()` (`/subtitles`), `getExternalSubtitles()` (`/subtitle/external`)
- Keep `getExternalSubtitles` endpoint if desired (it uses file scanning, not ffprobe) — **remove for now since frontend MPV handles this**

### 5. VideoScanService.java
- Remove `MediaInfoService` import and field
- Remove Phase 5 (ffprobe loop, lines 90-97)
- Update class javadoc to remove "ffprobe" mention

### 6. WatchProgressService.java
- Remove lines 41-46 (ffprobe duration override logic) — frontend MPV now provides accurate duration

### 7. application.yml
- Remove `ffprobe-path` and `ffmpeg-path` from `video:` section (lines 41-42)

### 8. VideoScrapeService.java
- No changes needed — it sets `durationMinutes` from TMDB, not ffprobe

## SQLite Migration
SQLite doesn't support `ALTER TABLE DROP COLUMN` in older versions. JPA/Hibernate with `spring.jpa.hibernate.ddl-auto=update` will simply ignore missing columns. No explicit migration needed — the old columns will remain in the DB but unused.
