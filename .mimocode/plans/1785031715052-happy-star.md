# SQLite → PostgreSQL 迁移计划

## 概述

将 fryfrog-hub-api 从 SQLite 迁移到 PostgreSQL，解决并发写冲突问题，同时优化表结构。

---

## Phase 1: 依赖变更

### 1.1 `app/pom.xml` — 替换数据库驱动

- **删除** `sqlite-jdbc:3.45.1.0` 依赖
- **删除** `hibernate-community-dialects` 依赖
- **新增** `org.postgresql:postgresql` (scope: runtime)
- **保留** `h2` (scope: runtime) — 测试用
- **保留** `mysql-connector-j` (scope: runtime) — 如果不需要可删除

### 1.2 删除 SQLite 方言引用

- `hibernate-community-dialects` 整个依赖移除（它提供了 `SQLiteDialect`）

---

## Phase 2: 配置变更

### 2.1 `app/src/main/resources/application.yml`

```yaml
spring:
  datasource:
    url: jdbc:postgresql://${DB_HOST:localhost}:${DB_PORT:5432}/${DB_NAME:fryfrog}
    username: ${DB_USERNAME:fryfrog}
    password: ${DB_PASSWORD:fryfrog}
    driver-class-name: org.postgresql.Driver
  jpa:
    hibernate:
      ddl-auto: update
    properties:
      hibernate:
        dialect: org.hibernate.dialect.PostgreSQLDialect
  hikari:
    maximum-pool-size: ${DB_POOL_SIZE:10}
    connection-timeout: 30000
```

**删除的 SQLite 特有配置：**
- `journal_mode=WAL`
- `busy_timeout=10000`
- `shared_cache=false`
- `DB_PATH` 环境变量

### 2.2 `app/src/main/resources/application-dev.yml`

同样替换为 PostgreSQL 连接配置（指向本地或 Docker PG）。

## Phase 3: 代码变更 — 删除 DatabaseWriteLock

PostgreSQL 支持真正的并发写入，不再需要应用层全局写锁。

### 需要修改的文件（7 个服务 + 1 个工具类）：

| 文件 | 改动 |
|------|------|
| `common/.../DatabaseWriteLock.java` | **删除整个文件** |
| `video/.../VideoScanService.java` | 移除所有 `DatabaseWriteLock.runInWriteLock()` 包裹，直接执行 |
| `video/.../VideoOrganizeService.java` | 移除 `DatabaseWriteLock.runInWriteLock()` 包裹 |
| `video/.../VideoScrapeService.java` | 移除 `DatabaseWriteLock.lock()/unlock()` 调用 |
| `video/.../VideoAssetService.java` | 移除 `DatabaseWriteLock.runInWriteLock()` 包裹 |
| `video/.../VideoService.java` | 移除 `DatabaseWriteLock.lock()/unlock()` |
| `video/.../VideoController.java` | 移除 `DatabaseWriteLock.runInWriteLock()` |
| `ebook/.../EbookService.java` | 移除 `DatabaseWriteLock.lock()/unlock()` |

**原则：** `@Transactional` 已经提供了事务保护，在 PostgreSQL 下足够。移除 `DatabaseWriteLock` 后代码更简洁，性能更好。

---

## Phase 4: SQLite 写锁重试逻辑清理

`WatchProgressService` 中为 SQLite 添加的 `retryOnLock` 重试逻辑（catch `CannotAcquireLockException`）在 PostgreSQL 下很少触发，但保留无害。**保留不删**，作为防御性编程。

## Phase 5: Docker 配置

### 5.1 `docker-compose.yml` — 新增 PostgreSQL 服务

```yaml

  postgres:
    image: postgres:16-alpine
    container_name: fryfrog-postgres
    restart: unless-stopped
    environment:
      POSTGRES_DB: ${DB_NAME:fryfrog}
      POSTGRES_USER: ${DB_USERNAME:fryfrog}
      POSTGRES_PASSWORD: ${DB_PASSWORD:fryfrog}
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports:
      - "${DB_PORT:5432}:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USERNAME:fryfrog}"]
      interval: 5s
      timeout: 5s
      retries: 5

  fryfrog-hub-api:
    image: ghcr.io/xbwsh/fryfrog-hub-api:latest
    container_name: fryfrog-hub-api
    restart: unless-stopped

  pgdata:
```

## Phase 6: 实体优化

### 6.1 `columnDefinition = "TEXT"` 清理

以下实体中的 `@Column(columnDefinition = "TEXT")` 在 PostgreSQL 中不需要（Hibernate 的 `String` 默认映射为 `varchar(255)`，但 PostgreSQL 的 `text` 类型性能与 `varchar` 无差异）。

**建议：** 保留 `columnDefinition = "TEXT"`，它在 PostgreSQL 中会正确创建 `text` 列。不需要改动。

涉及的实体：
- `Video` — overview, tags
- `VideoSeries` — overview
- `Comic` — summary, seriesSummary
- `MusicTrack` — lyrics
- `Ebook` — description
- `MediaSeries` — description
- `MediaSeriesCharacter` — (字段待查)
- `SystemSetting` — value, description

### 6.2 保留字列名转义

以下列名使用了保留字，需要引号转义：

| 实体 | 列 | 注解 |
|------|------|------|
| `Video` | `year` | `@Column(name = "\"year\"")` |
| `MusicTrack` | `year` | `@Column(name = "\"year\"")` |
| `Comic` | `year` | `@Column(name = "\"year\"")` |
| `Ebook` | `year` | `@Column(name = "\"year\"")` |
| `SystemSetting` | `key` | `@Column(name = "\"key\"")` |
| `SystemSetting` | `value` | `@Column(name = "\"value\"")` |

**PostgreSQL 兼容性：** `"year"` 在 PostgreSQL 中是合法的转义标识符，**无需改动**。

### 6.3 索引优化建议（可选）

当前索引已经覆盖主要查询场景，暂不需要调整。未来如果查询变慢可以再加。

## Phase 7: 数据迁移

提供一个迁移脚本，帮助用户将现有 SQLite 数据迁移到 PostgreSQL。

### 方案：Python 脚本（推荐）

创建 `scripts/migrate-sqlite-to-postgres.py`：

1. 读取 SQLite 数据库的所有表数据
2. 连接 PostgreSQL
3. 逐表插入数据（保留自增 ID）
4. 重置 PostgreSQL 序列（使后续插入不冲突）

**使用方式：**
```bash
pip install psycopg2-binary
python scripts/migrate-sqlite-to-postgres.py --sqlite ./fryfrog.db --pg-host localhost --pg-db fryfrog
```

### 方案：重新扫描（简单替代）

如果用户不在意观看进度等数据，可以直接：
1. 启动新 PostgreSQL 版本
2. 配置 media library 路径
3. 触发重新扫描

**建议：** 两个方案都提供，让用户自己选择。

## 风险点

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| `ddl-auto: update` 在 PostgreSQL 下可能产生不兼容的 DDL | 低（标准 JPA 注解） | 先在本地 PostgreSQL 测试 |
| `DatabaseWriteLock` 移除后并发安全性 | 无（PG 原生支持） | `@Transactional` 已保证 |
| 数据迁移脚本执行失败 | 中 | 提供"重新扫描"作为备选方案 |
| `columnDefinition = "TEXT"` 在 PG 下的行为 | 无（PG 原生支持 text 类型） | 已验证兼容 |
| 旧版 Docker 用户升级 | 中 | 在 README 中提供迁移指南 |
